## 1. Bottom line

1. **The spec's data choices hold up.** The night-lights frames, the map calibration and the sea-temperature frame date were each confirmed by an analyst agent, then by a second agent, then by a fact-checker who redid the calibration fit. [A, re-checked] Nothing in the spec depends on EIC data arriving daily.
2. **Three parts of the plan do not do what the spec says. All three are cheap to fix, and all three matter before tonight's gate.** Two critic agents found them by running the plan's own code on the real frames; their scripts were re-run for this file and gave the same numbers. [V]
   - **Gate G1 scores each listener on 2 rounds per type, not 5.** "70%" then means 3 of 4, which coin-flipping reaches 31% of the time. The decision to pivot rests on it.
   - **The Jukebox tab is nearly silent in meaning.** In the night-lights layer 99.9% of map cells land on the lowest three pitch steps, and Tokyo plays the same note as the empty Sahara. The sea-temperature layer says "land, no ocean data" over 60% of the map, the mid-Atlantic included.
   - **In the "match" round, night lights and lightning play the same notes** (only the pulse differs, 1.4 against 1.6 per second), and the plan's own test for this fails.
3. **The lightning frames can be dated, and the dates show the "season" answer key is wrong for 14 of its 31 rounds.** [V] NASA publishes a date for every frame of the flat lightning movie in a file called `labels.txt`; the first analysis missed it. Joined to the team's 40 frames, 17 keyed rounds fall in the summer they name and 14 are frames from May, September, October, November or March that the key calls a "summer". Issue 5.
4. **"Say value" says nothing for the user it was built for.** [V] The button and the V key speak only when the narration box is ticked, and the spec keeps it off for screen-reader users. Issue 6.
5. **Rules read from the live 2026 guide today.** [V] A demo longer than 30 seconds or 7 slides puts the project out of Global Judging. The deadline is 11:59 p.m. in the time zone of the team's Local Event. Local judging can be at a different time, and only the Local Lead knows when. The answer in the AI ("Super Intelligence") form field is not shown to judges, so AI-made code and audio have to be acknowledged inside the project itself, and AI is not allowed to be the source of the solution idea. Issue 8.
6. **"Daily" in the spec means date-seeded, and that is the right call.** The visualizations the challenge names are one-off renders; none changes from day to day. The EIC gallery does contain 23 products that NASA lists as updated daily (19 really are today), if we ever want something new each day (`06`, section 2b).
7. **The Jukebox has the fewest registered teams of the 14 challenges**: 654 of 20,879 worldwide, and 4 of 87 at Chicago, tied with four other challenges. [V, one browser capture; registrations, not submissions] It is still busy in public: a repository search returns more than 40 new "earth jukebox" repos, and one of them already decodes pixels to values with NASA's legend and ships an audio legend. [A, re-checked] `eic-data/competitors.md`
8. **A stronger validity result exists, if we add a layer.** Frames of the sea-temperature-anomaly product (SVS 5176), decoded with NASA's colour bar, reproduce NOAA's El Niño index with a correlation of 0.984. [V] It is a different product from the spec's ocean layer and does not validate that layer's decoding. `eic-data/data-test-sst-anomaly.md`

## 5. New and notable ideas

**A rule to keep in mind first.** The 2026 guide says AI may be used to speed the work up but should not be what comes up with the idea for solving the challenge, and that AI use must be declared. [V] Everything in this section was suggested by AI agents reading the data. Treat it as a list of what the data allows. Whether any of it becomes part of the project is the team's decision, and if it does, say so in the AI statement.

Ordered by value for effort. None is required for the spec as written.

1. **Put NASA's real dates into the lightning round.** `labels.txt` gives the date of any frame of the flat movie, so frames can be chosen by date instead of at fixed 2.5-second steps: for example the ten-day windows around each July and each January, 2017 to 2023. The season round then has an answer that is true independently of our pixel count, and the reveal can say "around 24 July 2017". The seven northern-summer peaks are plain in the team's own 40 frames. [V]
2. **Show each track's clock.** "One frame" means a year for night lights, a 10-day window for lightning, four hours of a 2007 ocean model. Stating that on each card and in each reveal is honest, costs only text, and no competitor README we read does it. `06`, section 2.
3. **A jump-to-place list for the Jukebox.** The pipeline already holds dozens of named cities and seas (`CITIES`, `OCEANS`). A plain list that moves the cursor and reads the value replaces dozens of button presses and is the cheapest large accessibility gain the critics found. [A]
4. **Add an El Niño track or round.** SVS 5176 (sea surface temperature anomaly) is in the EIC gallery, is a flat map, and has exactly one frame per day with the date in the file name. The decoded Niño 3.4 series sits near zero through 2025 and climbs to +3.3 °C by October 2026, matching NOAA's index at r = 0.984 over 128 weeks. [V] Costs: it is a fifth data page; the product is a rolling window about three days behind, so freeze a copy; the picture's colour scale stops at ±4 °C; and NOAA's index is not NASA data, so it goes in References. The judge agent rated it "if time", about two hours.
5. **Date the sea-temperature frames exactly.** NASA publishes the time of every frame of SVS 3912: time = 25 Mar 2007 12:00 UTC + (file number − 23000) × 3715.2 seconds. The five extra frames already downloaded are 26 Mar, 1 Apr, 19 Jun, 13 Sep and 8 Dec 2007. Only the June and December frames are clearly seasonal; the other three sit near an equinox. So this supports dated labels today, and a season round only if more frames near June and December are fetched. [A, re-checked]
6. **Borrow NASA's own recipe from the Caldwell 73 example the challenge links.** A visible cursor sweeps at constant speed, distance from the centre sets pitch, colour chooses the instrument, and the strongest pitches sit on an E-major pentatonic scale over a drone; about 30 seconds long. Its accessibility is thin: the caption file's entire text is "[ PRETTY MUSIC ]". Earthsound's spoken values and legend already exceed it. [A, re-checked, `eic-data/pages/13786.md`]
7. **Match the strongest public competitor on honesty.** One public repo decodes pixels with NASA's legend on two other SVS pages and has an audio legend (hear the lowest and the highest value). An audio legend plus a plain note on what the numbers are would put Earthsound level with it there, and the daily challenge and listener testing are things no README we read has. [A, re-checked]
8. **A genuinely daily card, later.** A scheduled GitHub Action could fetch NASA's newest daily frame and publish it as "today's ocean". Not for this weekend: it adds a moving part before a deadline.

Dropped from the first version: using the per-year night-lights stills on SVS 5276 for a "which year?" round. The whole map brightens by only about 3% over the eleven years, the files are 16-bit TIFFs in a different geometry from the spec's calibration, and nobody has checked that their background is transparent. The judge agent rated it "do not".
