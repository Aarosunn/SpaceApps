## Quick answer

- What it is: Flat world map of daily sea surface temperature (JPL MUR analysis), a rolling 901-day window where one frame is exactly one calendar day, re-rendered every morning; newest frame 13 Nov 2026 at the time of checking.
- Kind: data-animation
- Data source: JPL Multi-scale Ultra-high Resolution (MUR) Sea Surface Temperature Analysis, MUR-JPL-L4-GLOB-v4.1 (bundle line 15 and line 48-49). A Level-4 gap-filled analysis of observations, not a forecast model. (observation)
- Period covered: 2024-05-27 through 2026-11-13 inclusive = 901 consecutive days (about 2.47 years), as of the render that landed 2026-11-14 about 13:13-13:54 UTC. The window slides forward one day per daily render.
- Time step of the underlying data: 1 day (901 file names with consecutive YYYYMMDD dates, no gaps: dated_sets.json usual_step_s 86400, missing 0)
- **One frame equals**: 1 calendar day. Arithmetic: frame set has 901 files dated 2024-05-27..2026-11-13 and (2026-11-13 minus 2024-05-27) = 900 days, so 901 dates for 901 files. Movie: 30.03 s x 30 fps = 901 frames. Burned-in labels confirm: frame 0 = 27 May 2024, frame 270 = 21 Feb 2025 (270 days later), frame 570 = 18 Dec 2025 (570 days later), frame 870 = 14 Oct 2026, last frame 900 = 13 Nov 2026.
- **One frame = one day?**: yes
- Where a program gets a frame's date: Best: the frame-set file names (sst_mur_YYYYMMDD.exr, sst_mur_YYYYMMDD_no-dates.exr, ..._robinson.exr, ..._robinson_hurricane.exr); the directory listing is the only machine-readable date source. Second: formula index -> date (see frame_to_time_mapping). Third: label burned into the dated movie (would need OCR). There is no separate date-only overlay frame set and no JSON/metadata file with dates.
- Date label seen on screen: Dated variants: white text 'D Mon YYYY' (for example '27 May 2024', '13 Nov 2026') in the bottom-left corner on a semi-transparent dark rounded box. In the 1280x640 preview the box covers about x 0-183, y 578-640, i.e. roughly x 0-590, y 1850-2048 at 4096x2048 (scaled, inferred). No time of day, no time zone, no title, no units, no colorbar, no NASA logo in the equirectangular movies. Robinson variants: same date text bottom-left on the black corner outside the map ellipse, no box.
- Update behaviour: Re-rendered daily by an automated job (keyword 'Automated', series 'Updates Regularly'). Latest render (UTC, 2026-11-14): frame files 13:13-13:15 (listing shows 8:13-8:15 AM, which is US Eastern: EXR header capDate 2026:11:14 08:18:12 with utcOffset 18000 s = UTC-5), default mp4 13:17:50, no-dates mp4 13:29:46, robinson mp4 13:41:46, robinson_hurricane mp4 13:53:37, wLegend png 13:53:51. Newest data date 2026-11-13, so lag = 1 day (matches NASA's 'one day latency'). Rolling window = 901 frames. Whole set is rewritten each run: in all four frame folders the first and last file were modified on Nov 14, 2026 within about 2 minutes and the sampled files show only that one day. Old dates drop off the front (inferred from fixed 901 count; not observed across two days).
- Status on 2026-11-14: updating-daily — newest data: 2026-11-13 (last file sst_mur_20261113.exr; last movie frame label '13 Nov 2026')
- View / camera: Static flat map, no camera motion. Default / no-dates: equirectangular 2:1, 4096x2048, centered on 0 deg longitude, so lon = x/4096*360 - 180 and lat = 90 - y/2048*180 (checked against Australia's position in the preview; formula inferred, not documented by NASA). Robinson variants: ellipse-like world map on black background, pixel -> lat/lon needs an inverse Robinson transform. Geography is fixed in every frame.
- On-screen clutter: Dated movie: only the bottom-left date box. No-dates movie: nothing at all. Robinson hurricane variant adds diagonal black hatching over water warmer than 82 F; its wLegend still also adds a legend line '= Temperature above 82 F hurricane threshold' and a small colorbar titled 'Sea Surface Temperature', 'Degrees Fahrenheit' bottom-right. Land is dark gray shaded relief (R=G=B roughly), Antarctica/ice sheets lighter gray.
- Clean variant: Yes: sst_30_sec_no-dates_4096x2048_2x1_30p.mp4 and frame set sst_mur_no-dates/ (verified: last frame has no label, no colorbar). EXR frames are RGBA half-float, 4096x2048 (header of sst_mur_no-dates_most_recent.exr read by range request); they are rendered color images (RenderMan), not temperature values. Whether the alpha channel masks land is unknown (not decoded).
- What the colours mean: Color = sea surface temperature. Separate colorbar images: -5 to 35 deg C (labels -5,0,5,...,35, 'Degrees Celsius') or 23 to 95 deg F (labels 25..95, 'Degrees Fahrenheit'), title 'Sea Surface Temperature'. Dark navy (-5 C) -> blue -> pale blue just below 15 C, then an abrupt switch to cream at 15 C -> orange -> red -> dark maroon (35 C). Arrow ends mean values beyond the range saturate. Gray = land.
- Fit as a sonification source: **good** — Fixed flat geography, a clean no-label variant, an exact one-frame-per-day mapping with no gaps, a published colorbar, and it is live (yesterday's data today). The signal is dominated by the smooth seasonal cycle (warm band moving north and south), which is easy to hear but slow and repetitive: 2.5 cycles in the whole movie, little day-to-day drama. Values must be recovered from color through H.264 compression, and browsers cannot read the pixels straight from NASA's server.
- Suggested mapping: Split the map into latitude bands (for example 60-30N, 30N-Eq, Eq-30S, 30-60S), take the mean ocean color in each band per frame, convert to deg C with the colorbar lookup, and map temperature to pitch, one voice per band panned north = left / south = right; play about 10 days per second so a year lasts about 36 s, and speak the date (from the index -> date formula) through an aria-live region at each month boundary. Add an explore mode: arrow keys move a cursor over the map and the pitch follows the temperature under it, with a soft click over land.

## Frame → time mapping

date(i) = newest_date - (900 - i) days for movie frame index i = 0..900 (i = round(currentTime * 30)). For the render of 2026-11-14: date(i) = 2024-05-27 + i days. Do NOT hard-code the start date: the window slides daily, so read newest_date from the last file name in the frame-set directory listing (or from the burned-in label of the last frame) each time the movie is downloaded.

## Gotchas

- CORS (verified by HEAD request with Origin: http://localhost:5173): the server answers 'access-control-allow-origin: https://tempo.multiverse.music', a fixed foreign origin. A page on localhost or any other site can display the video/image, but canvas getImageData and fetch() of the file will fail. Download the files and serve them from the app's own origin.
- The window slides every day: frame index i is not a fixed date. A copy downloaded today and a copy downloaded tomorrow are offset by one frame. Store newest_date alongside any downloaded movie.
- Variants are rendered one after another over about 36 minutes (13:17 to 13:54 UTC on 2026-11-14), so during that window different variants can end on different dates.
- SVS 5101 and SVS 5176 are on different schedules and end on different dates (2026-11-13 vs 2026-11-11): the same frame index is 2 days apart between the two pages. Join them by date, not by index.
- Only one movie size exists (4096x2048, 88 MB). For a web demo, transcode to about 1024x512 with ffmpeg in WSL, or precompute per-frame numbers into a small JSON.
- EXR frames are rendered pictures (RGBA), not temperature grids; getting real deg C values means inverting the colormap. The colormap has an abrupt blue-to-cream break at 15 C and saturates below -5 C and above 35 C.
- Land is gray shaded relief and must be masked (near-equal R, G, B) before averaging; inland seas and large lakes are colored too.
- NASA text is out of date in places: the page says the frame sets have '902 item(s)' (description line says '0 Item(s)') but the listings hold 901 files; the description lists the mp4 as 78.0 MB but the file is 88,434,178 bytes.
- Frame-file times in the directory listing are US Eastern (8:13 AM = 13:13 UTC), not UTC.
- MUR is a gap-filled analysis: under cloud it is interpolated, so it is 'observation-based' rather than raw satellite pixels.
- Added by the second agent: Bundle 'numeric index step {1:870,70:16,71:10,8870:2}' is YYYYMMDD integer subtraction across month/year ends, not gaps. Real step is exactly 1 day; parse names as dates.
- Added by the second agent: Re-check Last-Modified or the listing at submission time: if the daily render runs, 5101 newest becomes 2026-11-14 and start 2024-05-28 (5101 renders ~13:17 UTC, 5176 ~21:16 UTC). Store newest_date with any copy you ship.
