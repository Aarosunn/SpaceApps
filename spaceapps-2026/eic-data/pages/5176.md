## Quick answer

- What it is: Flat world map of daily sea surface temperature anomaly (warmer or cooler than normal, -4 to +4 deg C), a rolling 901-day window where one frame is exactly one calendar day; newest frame 11 Nov 2026, rendered 13 Nov 2026 21:16 UTC.
- Kind: data-animation
- Data source: JPL Multi-scale Ultra-high Resolution (MUR) Sea Surface Temperature Analysis, MUR-JPL-L4-GLOB-v4.1 (bundle line 15 and lines 45-46). Anomaly = difference from a reference climatology; the baseline period is not stated on the page (unknown). (observation)
- Period covered: 2024-05-25 through 2026-11-11 inclusive = 901 consecutive days (about 2.47 years), as of the render that landed 2026-11-13 about 21:16-22:00 UTC. The window slides forward with each render.
- Time step of the underlying data: 1 day (901 file names with consecutive YYYYMMDD dates, no gaps: dated_sets.json usual_step_s 86400, missing 0)
- **One frame equals**: 1 calendar day. Arithmetic: 901 files dated 2024-05-25..2026-11-11 and (2026-11-11 minus 2024-05-25) = 900 days, so 901 dates for 901 files. Movie: 30.03 s x 30 fps = 901 frames. Burned-in labels confirm: frame 0 = 25 May 2024, frame 279 = 28 Feb 2025 (279 days later), frame 447 (t=14.90 s) = 15 Aug 2025, frame 585 = 31 Dec 2025, last frame 900 = 11 Nov 2026.
- **One frame = one day?**: yes
- Where a program gets a frame's date: Best: the frame-set file names (sst_mur_anomaly_YYYYMMDD.exr, sst_mur_anomaly_nodates_YYYYMMDD.exr, sst_mur_anomaly_pacific_YYYYMMDD.exr, sst_mur_anomaly_robinson_YYYYMMDD.exr); the directory listing is the only machine-readable date source. Second: formula index -> date. Third: the label burned into the dated movies (would need OCR). No separate date-only overlay set, no metadata file.
- Date label seen on screen: Dated variants (default, Pacific, Robinson): white text 'D Mon YYYY' (for example '25 May 2024', '11 Nov 2026') bottom-left on a semi-transparent dark rounded box, about x 0-183, y 578-640 in the 1280x640 preview, i.e. roughly x 0-590, y 1850-2048 at 4096x2048 (scaled, inferred). Robinson: text on the black corner, no box. No time of day, time zone, title, units, colorbar or NASA logo in the movies.
- Update behaviour: Re-rendered by an automated job (keyword 'Automated', series 'Updates Regularly'). Latest render (UTC, 2026-11-13): default mp4 21:16:29, nodates mp4 21:31:36, pacific mp4 21:46:09 (frame files 4:40-4:42 PM US Eastern = 21:40-21:42 UTC), robinson mp4 21:59:38 (frames 4:54-4:56 PM Eastern). Newest data date 2026-11-11, so lag = 2 days at render time, and 3 days behind the calendar when checked at 2026-11-14 19:28 UTC (a HEAD request then still showed Last-Modified Fri, 13 Nov 2026 21:16:29 GMT). NASA's text claims 'one day latency': the files disagree. Rolling window = 901 frames. Whole set rewritten per run: pacific and robinson folders show first and last file modified on Nov 13, 2026 only; the default and nodates folder listings carry no modified times (unknown for those two, same file names and count).
- Status on 2026-11-14: updating-daily — newest data: 2026-11-11 (last file sst_mur_anomaly_20261111.exr; last movie frame label '11 Nov 2026')
- View / camera: Static flat map, no camera motion. Default / nodates: equirectangular 2:1, 4096x2048, centered on 0 deg longitude (lon = x/4096*360 - 180, lat = 90 - y/2048*180; inferred from layout, checked against Australia). Pacific variant: same projection centered on 180 deg (x = lon_east/360*4096 for lon 0..360; Australia sits at x 410-545 of 1280 as that predicts). Robinson variant: ellipse-like map on black, needs inverse Robinson. Geography fixed in every frame.
- On-screen clutter: Dated movies: only the bottom-left date box. Nodates movie: nothing. Land is dark gray shaded relief. Lighter flat gray patches over polar ocean (Arctic, around Antarctica, Hudson Bay) change from frame to frame and look like a sea-ice / no-data mask (inferred; NASA does not explain them).
- Clean variant: Yes: sst_anomaly_nodates_30_sec_4096x2048_2x1_30p.mp4 and frame set sst_mur_anomaly_nodates/ (verified: last frame has no label). No dated-free Pacific or Robinson variant. EXR frames are RGBA half-float 4096x2048 rendered images (header of sst_mur_anomaly_nodates_most_recent.exr read by range request), not anomaly values. No alpha/overlay-only layers are offered.
- What the colours mean: Color = SST anomaly in deg C relative to normal for that day of year. Separate colorbar image: title 'Sea Surface Temperature Anomaly', ticks -4 -3 -2 -1 0 1 2 3 4, 'Degrees Celsius'. Dark navy (-4) -> blue -> pale blue just below 0, abrupt switch to cream at 0 -> orange -> red -> dark maroon (+4). Blue = cooler than normal, orange/red = warmer than normal; arrow ends mean values beyond +/-4 saturate. Dark gray = land, light gray = ice/no data (inferred).
- Fit as a sonification source: **excellent** — Same clean technical properties as 5101 (fixed flat map, no-label variant, exact one frame per day, no gaps, published colorbar) but the content is far more eventful: a signed quantity around zero with clear regional stories, for example the last frame (11 Nov 2026) shows a deep dark-red tongue along the equatorial eastern Pacific off South America while the 2025 frames do not. A diverging scale maps naturally to sound (warm vs cool = two timbres or up vs down in pitch). Costs: the movie is 363 MB, values must be recovered from color through video compression, CORS forces self-hosting, and the newest data is 2 to 3 days old.
- Suggested mapping: Average the anomaly inside a few named ocean boxes per frame and give each box a voice: sign chooses timbre (warm = bright brass-like, cool = soft flute-like), magnitude sets loudness and distance from a center pitch. Start with the Nino 3.4 box (5N-5S, 170W-120W): in the Greenwich-centered 4096x2048 frame that is about x 114-683, y 967-1081; in the Pacific-centered frame about x 2162-2731, same y (computed from the equirectangular formula). Play about 10 days per second, announce month and year from the index -> date formula via aria-live, and let the user step day by day with arrow keys.

## Frame → time mapping

date(i) = newest_date - (900 - i) days for movie frame index i = 0..900 (i = round(currentTime * 30)). For the render of 2026-11-13: date(i) = 2024-05-25 + i days. Do NOT hard-code the start date: read newest_date from the last file name in the frame-set directory listing each time, because the window slides.

## Gotchas

- The team summary cites 'SVS 5176' as easy, no-login data (00-SUMMARY.md line 48). True for download (HTTP 200, no login), but it is rendered color pictures, not numbers, and CORS is locked: a HEAD request with Origin: http://localhost:5173 returned 'access-control-allow-origin: https://tempo.multiverse.music'. A browser app on any other origin can show the video but cannot read its pixels or fetch() it. Download and serve from your own origin.
- Lag is 2 days at render time, not the 'one day latency' NASA states: render 2026-11-13 21:16 UTC, newest data 2026-11-11. SVS 5101 the next morning already had 2026-11-13.
- 5176 and 5101 end on different dates and render at different times of day (5176 about 21:16 UTC, 5101 about 13:17 UTC). Same frame index = dates 2 days apart. Join by date.
- The window slides with each render: frame index i is not a fixed date, and the oldest file names disappear. Store newest_date with every downloaded copy.
- Movies are 362-363 MB each at 4096x2048 with no smaller version. Do not stream them from NASA in a demo; transcode to about 1024x512 (WSL ffmpeg) or precompute per-frame box averages into JSON.
- NASA's caption for media group 372465 calls the no-datestamp item a 'still image' but it is a 901-frame movie plus frame set (bundle lines 72-73).
- Page says frame sets have '902 item(s)' (description line: '0 Item(s)'); listings hold 901 files. Description lists the mp4 as 338.0 MB; the file is 362,077,985 bytes.
- Three kinds of non-data pixels must be masked before averaging: dark gray land, light gray polar patches (ice/no data, inferred), and the date box in dated variants. Near-zero anomaly colors are pale (cream / pale blue), so separate them from light gray by color saturation, not brightness alone.
- The colormap switches abruptly from pale blue to cream at 0 and saturates beyond +/-4 deg C, so extremes (the dark maroon Pacific tongue) are clipped: you cannot tell +4 from +6.
- File naming differs from 5101 (variant before the date here, after the date there); the default and nodates directory listings here are name-only (no size or modified time).
- Variants render about 15 minutes apart (21:16, 21:31, 21:46, 21:59 UTC), so they can briefly disagree on the newest date.
- Added by the second agent: At 20:17 UTC on 14 Nov the 5176 window still ended 11 Nov (3 days behind). Do not promise live daily for 5176; say updated regularly with about a 2-day lag.
- Added by the second agent: The Pacific-centered variant is dated-only (no nodates Pacific), so the bottom-left date box must be masked when averaging.
